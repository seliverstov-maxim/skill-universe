# Skill Universe

A Unix CLI for installing and updating skills and rules from Git repositories for Codex and Claude. No telemetry or central catalog.

Release: **[v2.0.01](https://github.com/seliverstov-maxim/skill-universe/tree/v2.0.01)**. Incompatible with version 1; start with a fresh manifest using `init`.

Contributions go to `develop`; installation and tool upgrades use released `main`. See [contributing](CONTRIBUTING.md) and the [maintainer release flow](RELEASING.md). Audit reports identify their reviewed release source, not unreleased changes on `develop`.

## Installation

For macOS and Linux. Requires a Unix shell, Git, and `jq`.

```sh
curl -fsSL https://seliverstov-maxim.github.io/skill-universe/install.sh | sh
```

Clones into `~/.skill-universe/tool/` and links the command in `~/.local/bin/`. The installer prints PATH instructions. Its full contents:

```sh
#!/bin/sh
# shellcheck disable=SC2034 # Some embedded defaults are CLI-only.
set -eu
# Generated by scripts/generate-installer.sh; edit env.sh and scripts/install-body.sh.
#!/bin/sh
# Shared defaults. The standalone installers embed this file; see scripts/generate-installer.sh.
# shellcheck disable=SC2034 # Values are consumed by sourcing commands and the installer body.
SKILL_UNIVERSE_HOME=${SKILL_UNIVERSE_HOME:-"$HOME/.skill-universe"}
SKILL_UNIVERSE_BIN_DIR=${SKILL_UNIVERSE_BIN_DIR:-"$HOME/.local/bin"}
SU_CODEX_HOME=${SU_CODEX_HOME:-"$HOME/.codex"}
SU_CLAUDE_HOME=${SU_CLAUDE_HOME:-"$HOME/.claude"}
SU_REPO_URL=${SU_REPO_URL:-"https://github.com/seliverstov-maxim/skill-universe.git"}
tool_branch=main
codex_skills_directory="$HOME/.agents/skills"
codex_rules_directory="$SU_CODEX_HOME/rules"
claude_skills_directory="$SU_CLAUDE_HOME/skills"
claude_rules_directory="$SU_CLAUDE_HOME/rules"
#!/bin/sh
# Embedded after env.sh by generate-installer.sh.
# shellcheck disable=SC2154 # Shared values come from the embedded environment module.
state=$SKILL_UNIVERSE_HOME
bin=$SKILL_UNIVERSE_BIN_DIR
for directory in "$state" "$bin"; do
    case "$directory" in /*) ;; *) printf 'Expected an absolute path: %s\n' "$directory" >&2; exit 1 ;; esac
done
for destination in "$state/tool" "$bin/skill-universe"; do
    if [ -e "$destination" ] || [ -L "$destination" ]; then
        printf 'Destination already exists: %s\n' "$destination" >&2
        exit 1
    fi
done

git clone --branch "$tool_branch" -- "$SU_REPO_URL" "$state/tool"
chmod +x "$state/tool/skill-universe"
mkdir -p "$bin"
ln -s "$state/tool/skill-universe" "$bin/skill-universe"
printf 'Installed: %s/skill-universe\n' "$bin"
printf 'Add this directory to your PATH: %s\n' "$bin"
```

```sh
skill-universe --version
```

## Usage

Choose Codex, Claude, or both:

```sh
skill-universe init --harness=codex,claude
```

For Codex, `init` adds a marked instruction block to `AGENTS.md` to read installed Markdown rules. Existing personal text is preserved. Claude loads its user rules directory directly.

Install a repository, or select a skill or rule:

```sh
skill-universe install <repo-url>
skill-universe install <repo-url> --branch=<branch> --skill=<skill-name> --alias=<alias>
skill-universe install <repo-url> --rule=<rule-name> --alias=<alias>
```

Without selectors, installs all skills and rules from the default branch. Aliases default to skill directory names or rule filenames without `.md` and must be unique across both types. Use `--alias` to resolve duplicates.

Names and aliases accept ASCII letters, digits, `.`, `_`, and `-`, except `.` and `..`. `--skill` and `--rule` cannot be combined. `--alias` requires one of them.

```sh
skill-universe list
skill-universe rename <alias> <new-alias>
skill-universe update <alias>
skill-universe update all
skill-universe remove <alias>
skill-universe upgrade
skill-universe --help
```

Items with the same repository URL and branch share a checkout. Updating one updates them all. Local edits are allowed; updates require a fast-forward, disable automatic stashing, and refuse to overwrite ignored files.

`upgrade` uses the Git URL and branch saved in the manifest by `init`. The default source is this repository's `main` branch; set `SU_REPO_URL` during installation and `init` to use another repository.

## Files and configuration

- Manifest: `~/.skill-universe/manifest.json`.
- Repository checkouts: `~/.skill-universe/repos/`.
- Skills: `~/.agents/skills/` for Codex; `~/.claude/skills/` for Claude.
- Rules: `~/.codex/rules/` for Codex; `~/.claude/rules/` for Claude.

Skills and rules are symlinked into the configured harness directories. Codex `init` connects rules through a `skill-universe:rules` block in `SU_CODEX_HOME/AGENTS.md`, creating the file if needed and preserving existing personal text. Later install, update, rename and remove commands do not edit personal instructions or configuration. Claude reads its user rules directory directly.

Edit `directory`, `rules_directory`, or the `upgrade` Git source in the manifest to change them. If you change the Codex rules directory, update its instruction block too.

| Environment variable | Purpose / default |
| --- | --- |
| `SKILL_UNIVERSE_HOME` | State, manifest, cache and tool checkout: `~/.skill-universe`. |
| `SKILL_UNIVERSE_BIN_DIR` | Installer command directory: `~/.local/bin`. |
| `SU_CODEX_HOME` | Codex instruction/rules root: `~/.codex`. Skills default to `~/.agents/skills`. |
| `SU_CLAUDE_HOME` | Claude skill/rule root: `~/.claude`. |
| `SU_REPO_URL` | Tool Git source for installation and new manifests; defaults to this repository. |

Defaults are defined in [env.sh](env.sh). Directory overrides must be absolute paths. The native `CODEX_HOME` and `CLAUDE_CONFIG_DIR` variables are not read. Harness overrides apply during `init`; edit the manifest for existing installations. They choose delivery paths, not the harness's active profile. Keep the state override consistent across commands. Export `SU_REPO_URL` for both installation and `init` to keep the same upgrade source; changing it later does not rewrite an existing manifest.

## Skill and rule repository structure

```text
repository/
|-- skills/
|   `-- skill-name/
|       `-- SKILL.md
`-- rules/
    `-- rule-name.md
```

- A skill requires `skills/<skill-name>/SKILL.md`. The entire directory is linked, including supporting files.
- A rule is `rules/<rule-name>.md`. No frontmatter is required; contents are preserved.
- Either directory may be omitted. Discovery covers immediate skill directories and immediate `.md` rule files. Root-level `SKILL.md`, nested rules and other rule extensions are ignored.
- Symlinks anywhere under `skills/` or `rules/`, including those directories themselves, are rejected. Updates check the incoming Git tree before applying it.
- `--skill` selects a directory name; `--rule` selects a filename without `.md`.
